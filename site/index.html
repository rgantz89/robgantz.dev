03 How I work

I look for the system behind the symptom

Most operations problems are connection problems: data that never meets, steps that repeat, warnings that show up before the outage. That is where I start.

Systems thinking

See the whole chain

I map how tickets, documents, network topology, maintenance calendars, and impact data affect each other, then build one tool that connects them instead of five that don't.

The governance platform joins all five sources into a single decision per change.
Pattern recognition

Spot the repeat before it costs

I look for signatures: two changes on the same ring in the same window, the same failure showing up across outages, the same manual step done every day.

Conflict detection flags overlapping maintenance windows across teams before anyone approves.
Automation

Turn the repeat into a run

Once a pattern is clear, I write it down as rules and tests so it runs on its own and stays right as the network changes.

Conflict-detection automation saved each analyst about 2 hours a day and earned a Charter Champions Award.
