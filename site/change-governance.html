Work / Case study in production

Change governance platform

A Python rules engine that checks each network change against its attachments, flags conflicts between teams, and replaced manual pre-approval review.

RoleSole developer
Scale700+ changes / day
Users15 change approvers
StackPython, SQL Server, GitLab CI/CD
In 30 seconds
Problem

Hundreds of network changes a day were pre-approved by hand, and conflicts between teams slipped through.

Built

A Python rules engine that reads every attachment, runs 35 checks, and ranks the queue by risk and conflict.

Result

Review time per change cut in half. 15 approvers cover more tickets and focus on the changes that could cause outages.

01 How it works

From raw queue to ranked worklist

01 · The problem

Hundreds of changes, read by hand

Every night, hundreds of maintenance changes across 9 verticals need pre-approval. Reviewers read each ticket and its attachments by hand, and two changes hitting the same part of the network in the same window are easy to miss.

review-queue
synthetic data

CHG-0103 Transport 3 files manual review
CHG-0104 Voice 1 file manual review
CHG-0105 Video 2 files manual review
No ranking, no conflict view. Every ticket and attachment read by hand.
02 · What I built

A rules engine that reads everything

Changes are pulled incrementally from SQL Server. Text is extracted from every attachment, including OCR on pasted images, and 35 checks run against topology, maintenance-window calendars, and impact data.

Cross-referenced against topology, maintenance-window calendars, and impact data.
03 · The result

A ranked worklist, conflicts flagged

Approvers get a ranked list instead of a raw queue, with conflicts flagged before anyone approves. Review time per change dropped by half, so the 15 approvers now cover more tickets and spend their attention on the changes most likely to cause an outage.

03 When it misses

Fixed within the hour

No rules engine catches everything. What matters is how fast a miss turns into a permanent fix.

Missed flaga change slipped through
Root causeanalyzed the fault
Fix in pipelinetests run before deploy
Live in under 1 hourno further impact

When the platform has missed a flag, we analyzed the fault and shipped the fix through the GitLab pipeline within the hour, preventing further impact. Every fix goes through the same 2,000+ test suite as any other release.
